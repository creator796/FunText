# FunText

FunText — ранняя бета браузерного мессенджера на GitHub Pages + Supabase.

## Реализовано в коде

- E2EE для текста новых сообщений через Web Crypto AES-256-GCM; ключ генерируется в браузере и не отправляется в Supabase.
- Защищённое приглашение формата `КОД.КЛЮЧ`; передавайте его только участникам через отдельный доверенный канал.
- Ключи хранятся в localStorage текущего браузера. Потеря ключа означает невозможность расшифровать историю.

- Анонимная Supabase Auth-сессия, сохраняемая в браузере.
- Создание облачных бесед через RPC-функцию.
- Присоединение к беседе по коду приглашения.
- Окно информации о группе с кодом приглашения и списком участников.
- Владелец может исключать участников, менять название и обновлять код приглашения.
- Участник может выйти из группы; владелец может удалить группу и её историю.
- Дополнительная миграция управления группами: `supabase/migrations/202610130003_group_management.sql`.
- Сохранение и загрузка истории сообщений.
- Получение новых сообщений через Supabase Realtime.
- RLS: читать беседы и сообщения могут только участники; отправитель должен совпадать с текущей сессией.
- «Избранное» сохраняется локально в браузере.
- Вложения до 10 МБ в приватном Supabase Storage.
- HTML-предпросмотр в sandboxed iframe: JavaScript и внешние ресурсы блокируются.

## Обязательная настройка базы

После обновления E2EE дополнительно выполни `supabase/migrations/202610130004_e2ee_message_size.sql` в Supabase SQL Editor, чтобы разрешить хранить зашифрованный текст (он длиннее исходного).

Откройте Supabase Dashboard → SQL Editor → New query, вставьте и выполните весь файл:

`supabase/migrations/202610130001_funtext_chat.sql`

Пока этот SQL не выполнен, облачные беседы не заработают, даже если анонимная авторизация уже подключена.

Сайт: https://creator796.github.io/FunText/

## Приватность и ограничения безопасности

- В HTML включён `Referrer-Policy: no-referrer`, а логотипы тем рисуются локально, чтобы не отправлять запросы на сторонние сайты только ради изображений.
- Предпросмотр HTML загружает вложение без заголовка Referer и блокирует JavaScript/внешние ресурсы внутри sandbox.
- Это уменьшает лишние утечки, но не скрывает IP от Supabase и не делает приложение анонимным на уровне сети.

- Это не Tor и не система гарантированной анонимности.
- E2EE пока покрывает только текст новых сообщений. Вложения, названия бесед, список участников, время отправки и другие метаданные не зашифрованы сквозным шифрованием.
- Это первая версия протокола E2EE без независимого аудита. Не используйте её для критически важных секретов до проверки специалистом.
- Потеря данных браузера может лишить доступа к анонимной сессии; восстановление аккаунта не реализовано.
- Вложения и их имена пока не зашифрованы сквозным шифрованием; HTML-предпросмотр изолирован sandbox.
- Код приглашения даёт доступ к беседе; передавайте его только нужным людям.
- Публичный Supabase publishable key допустим во фронтенде только при корректных RLS-политиках. Никогда не публикуйте service_role или secret key.
